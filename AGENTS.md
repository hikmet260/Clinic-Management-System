## Repo state (important)
Early-stage scaffold with a **root README.md** (setup, roles, modules, testing, deployment) and a Postgres `docker-compose.yml`; CI (`.github/workflows/ci.yml`) runs typecheck+build for both packages **plus a server e2e job** (Vitest + Postgres service container), and `.github/workflows/deploy.yml` builds + uploads artifacts on `main`.

Real so far:

Visit check-in with daily auto-incrementing token (`POST /api/queue/register`), today's queue (`GET /api/queue`, NURSE+RECEPTIONIST+DOCTOR) with `hasVitals`/`hasConsultation`. **Visit lifecycle**: `PATCH /api/queue/:id/cancel` (RECEPTIONIST, active visits only) and `PATCH /api/queue/:id/complete` (RECEPTIONIST+CASHIER, BILLED only) — both broadcast on the queue socket. `registerVisit` validates UUID format (400) and rejects a second active visit the same day (400). Token allocation is race-safe: a per-day `pg_advisory_xact_lock` transaction serializes same-day inserts, backed by a `(date(created_at), token_number)` unique index (`queue_daily_token_unique`) + retry on 23505.
- `packages/server/src/modules/vitals/*` — NURSE-only triage: `POST /api/vitals` upserts one vitals row per visit (validates ranges, computes BMI from weight+height) and marks the visit `TRIAGED`; `GET /api/vitals/:queueId` fetches it (404 if none). Terminal visits (BILLED/COMPLETED/CANCELLED) reject new vitals.
- `packages/server/src/modules/consultations/*` — DOCTOR-only SOAP notes: `POST /api/consultations` upserts one row per visit (requires non-empty subjective/objective/assessment/plan, optional ICD-10 code+description) and marks the visit `IN_CONSULTATION`; `GET /api/consultations/:queueId` fetches it (404 if none). Terminal visits reject new notes. `GET /api/queue` and `GET /api/vitals/:queueId` are also DOCTOR-readable; queue list carries `hasConsultation` (left-join on consultations).
- `packages/server/src/modules/billing/*` — CASHIER-only invoicing: `POST /api/billing` validates itemized line items + discount, computes subtotal/total, rejects terminal visits and duplicate invoices, and marks the visit `BILLED`; `GET /api/billing/queue` lists today's visits with their invoice summary (left-join on invoices); `GET /api/billing/:queueId` fetches an invoice (404 if none); `PATCH /api/billing/:invoiceId` marks it paid (400 if already paid). Decimal money fields are stored/computed as strings (`.toFixed(2)`).
- `packages/server/src/modules/lab-orders/*` — DOCTOR orders lab tests (`POST /api/lab-orders` requires an existing consultation and sets the visit `LAB_PENDING`); `GET /api/lab-orders` lists today's orders joined with patient/visit info (pending first, DOCTOR+LAB_TECH readable); `GET /api/lab-orders/:queueId` lists a visit's orders; `PATCH /api/lab-orders/:orderId` (LAB_TECH) completes (requires non-empty result) or cancels an order and, when the last pending order for the visit is resolved, flips the visit back to `IN_CONSULTATION`.
- `packages/server/src/modules/prescriptions/*` — DOCTOR-only prescriptions: `POST /api/prescriptions` upserts one row per consultation (requires an existing consultation, at least one named medication; medications are a `jsonb` array `{name, dosage?, frequency?, duration?, instructions?}` with empty optional fields stripped) and does **not** change visit status; `GET /api/prescriptions/:queueId` fetches it (404 if none). Terminal visits (BILLED/COMPLETED/CANCELLED) reject new prescriptions.
- `packages/server/src/modules/users/*` — ADMIN-only staff management: `GET /api/users` (no password hashes), `POST /api/users` (validates email format, 8-char password, role enum, duplicate email → 409), `PATCH /api/users/:id` (fullName/email/role/optional password reset), `DELETE /api/users/:id`.

## Not a real monorepo
- Root `package.json` has **no workspace and no shared lockfile**; it only holds `concurrently` and convenience scripts. **`pnpm dev` at the root starts both packages** (API via `nest start --watch`, web via vite) — this is the expected way to run the project.
- Each package has its own `node_modules` and `pnpm-lock.yaml`. Run `pnpm` commands from inside `packages/client` or `packages/server` — never from the root (except `pnpm dev`, `pnpm install`, `pnpm dev:install`).
- All three package.json files define `scripts`: both packages have `dev`/`build`/`typecheck`; server also `start`, `start:dev`, `seed`; root also `dev:install`.

## Server (`packages/server`) — NestJS 11 + Drizzle + postgres-js
- Postgres: `DATABASE_URL`, falling back to `postgres://clinic_user:clinic_password@localhost:5432/clinic_db`. Bring up the DB with `docker compose up -d` (root `docker-compose.yml`, env-overridable via `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB`/`POSTGRES_PORT`; see `.env.example`).
- Fresh-DB workflow: `docker compose up -d` (if needed) then `pnpm run db:migrate` (applies `packages/server/drizzle/0000_*.sql` via `src/database/migrate.ts`) then `pnpm run seed`. For an existing DB that was `db:push`ed, run `docker compose down -v` first or keep using `pnpm run db:push` (dev-only). `schema.ts` is the single source of truth — regenerate with `pnpm run db:generate` when the schema changes, and commit the new SQL file.
- Seed users (password `password123`): `admin@clinic.com` (ADMIN), `doctor@clinic.com`, `nurse@clinic.com`, `receptionist@clinic.com`, `cashier@clinic.com`, `labtech@clinic.com` (LAB_TECH).
- Drizzle is injected via `@Inject(DRIZZLE)`; controllers inject `PostgresJsDatabase<typeof schema>`.
- `pnpm-workspace.yaml` `allowBuilds` for `bcrypt`/`esbuild` is set to `true` (was blocking their postinstall). If a native module breaks, check this file.
- Roles (order-sensitive enum): `ADMIN, DOCTOR, NURSE, RECEPTIONIST, CASHIER, LAB_TECH`.
- JWT: Bearer token, `JWT_SECRET` env (dev fallback `super-secret-key-change-in-prod`), 8h expiry. Global guards make **every route require auth by default** — use `@Public()` for exceptions and `@Roles('...')` for role gating.
- Security hardening (in `main.ts`/`app.module.ts`): `helmet` headers, body-parser limit `16kb`, CORS allowlist (env `CORS_ORIGIN`, default `http://localhost:5173`), `X-Powered-By` disabled, optional `TRUST_PROXY`, global `@nestjs/throttler` rate limit (env `RATE_LIMIT_MAX`/`RATE_LIMIT_TTL_MS`, default 100/min) + tighter login throttle (env `LOGIN_RATE_LIMIT`, default 15/min), and **fail-fast in production** (refuses to boot without a strong `JWT_SECRET` and a `DATABASE_URL`). A global `LoggingInterceptor` logs every request (method, path, status, duration).
- `express` is a **direct** dependency (imported by `main.ts`); `rxjs` and `@nestjs/throttler` are direct deps too. `tsconfig.json` has `esModuleInterop: true` for the `helmet` default import. Beware: pnpm's isolated layout means `node dist/main.js` won't resolve packages that are only transitive deps.
- `tsconfig.json` sets `rootDir: ./src` (so `dist/main.js`, `dist/database/seeders/seed.js`, `dist/database/migrate.js` land correctly), excludes `drizzle.config.ts` + `vitest.config.mts`, and points `tsBuildInfoFile` into `dist/`. This keeps `rm -rf dist` a complete reset — if tsc ever emits nothing for "unchanged" files, the build-info was stale (it previously lived beside the tsconfig and survived `rm -rf dist`).
- E2e tests: Vitest + supertest under `src/test/*.e2e-spec.ts` (auth/queue/vitals/billing), run via `pnpm test` (`vitest run`, config `vitest.config.mts`). Needs a running Postgres; global setup auto-creates the `clinic_test` DB (role must have `CREATEDB`), applies migrations, and seeds users with **fixed UUIDs** (`11111111-…` … `66666666-…`) so JWTs minted in `beforeAll` stay valid across `beforeEach` truncate+reseed. Test files are typechecked by `tsc` since they live under `src`. CI runs this suite in a Postgres service container.

## Client (`packages/client`) — React 19 + Vite 8 + Tailwind 4 + Dexie
- `"type": "module"` in package.json; TS strict, `noEmit`. Dev server proxies `/api` → `http://localhost:3000` (Vite on :5173, API on :3000).
- Auth flow: `AuthProvider` (localStorage `clinic_token`/`clinic_user`) → `useAuth()` hook; `lib/api-client.ts` wraps fetch (Bearer injection, 401 clears token).
- Routes in `src/routes/index.tsx`: `/login` public; protected pages per role (`/queue` RECEPTIONIST, `/patients` RECEPTIONIST+ADMIN, `/triage` NURSE, `/consultation` DOCTOR, `/lab` LAB_TECH, `/billing` CASHIER, `/analytics` ADMIN, `/users` ADMIN). `/` redirects by role via `ROLE_HOMES`.
- Offline-first: `lib/dexie-db.ts` (`vitals`/`consultations` with `synced` flag); `hooks/use-offline-sync.ts` is real — `enqueueVitalsOffline`/`enqueueConsultationOffline` fall back to IndexedDB when a POST fails with a network `TypeError`, `flushPendingSync()` replays queued rows on `online` (per-row via a shared `replay` helper; permanently-rejected 4xx rows are dropped so one bad row can't block the queue), and `useOfflineSync()` exposes `{isOnline, pendingCount, syncing, flushPending}` (Header shows an offline/pending/syncing pill; auto-flushes on mount if already online). `vitals-form.tsx` + `soap-form.tsx` queue offline and surface an amber "Saved offline" notice.
- PWA: `src/sw.ts` service worker is compiled to `dist/sw.js` by the `clinic-service-worker` Vite plugin (uses `transformWithOxc`, NOT the deprecated `transformWithEsbuild` — Vite 8/rolldown requires esbuild installed separately). Dev serves it at `/sw.js` via middleware; it's registered in `main.tsx` only in `import.meta.env.PROD`. Cache strategy: network-first for navigations (fallback to cached shell), cache-first for `/assets/`, `/api/*` + `/socket.io/*` bypassed (offline writes go through the Dexie queue instead). `public/manifest.webmanifest` + `public/icon.svg` wired in `index.html`. Note: TS 7 moved SW globals (`ServiceWorkerGlobalScope`, `FetchEvent`, `ExtendableEvent`) out of `lib.dom` into `lib.webworker`, which can't be mixed into the DOM compilation — `sw.ts` declares its own minimal event/scope types. `tsconfig.json` includes `"node"` in `types` (for `vite.config.ts`; `@types/node` is a devDependency).
- Intended realtime: socket.io-client + server `queue.gateway.ts` (empty stub).
